# B2: Eval scores, security scan, telemetry and allowlists

## Decisions

- Eval score is not filled. I ran `claude plugin eval plugins/blueprint-ship` once: it rejects every case with `unknown frontmatter key "skill_sha256"` and loads none. That key is the repo's own pin, required by `check-evals`, so the two tools disagree. Fixing it means changing the eval format of existing cases, which is outside my paths. The loader (`--reports`) is ready and tested for a report shape of `{cases:[{name,score}]}`. This shape is my assumption, since no real report existed. Check it against real output.
- The gate makes no model calls, so scores are produced by the nightly run and stored by `scores --reports`.
- No new `kaas-blueprint` CLI command, so no MCP parity work. The trust tool is `node src/trust/cli.mjs`. Adding `scan` and `allowlist` as real commands with MCP tools needs edits to `bin/` and `tests/mcp.test.mjs` (which asserts exactly four tools), outside my paths.
- Security floor is 70. The only finding is a network word in `first-run`.
- Own-entry pins for the three new skills use the same commit sha as the B1 entries. Release should move them to the tag.
- Telemetry sends nothing. It only writes a local file. A sender needs an endpoint and a privacy decision for the operator.
- Evidence ledger and allowlist follow the idea of autoharness and Cursor/Factory allowlists. No code was ported, so no THIRD_PARTY_NOTICES entry.
- Test edits: none to existing tests. The routing prompts for two new skills were reworded until the ranker picked them first.
